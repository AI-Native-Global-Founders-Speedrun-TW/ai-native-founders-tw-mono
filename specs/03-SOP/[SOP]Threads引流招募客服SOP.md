# Threads 引流招募客服 SOP

# Problem

每位負責人可能使用不同帳號發起招募，詢問也會散在不同貼文、留言與私訊。若流程綁定特定貼文或個人，其他人就難以接續；同一人出現在多處時，也容易漏回或重複邀請。這份 SOP 提供共同處理方式，減少[加入申請的處理成本](<[SOP]志工協作與開源知識.md#我們能不能減少我們的營運成本>)。

# Specs

## 處理範圍

適用於任何透過 Threads 發起招募、回覆留言或處理加入詢問的人。可以從新貼文開始，也可以接續既有對話，不限定特定帳號、貼文或發文時間。

本組織目前使用 Discord，加入方式依[申請制度](<../01-制度/[機制] 憲政制度.md>)；執行前確認最新安排。

這是單方面邀請，以訊息送出為完成，不主動追蹤對方是否已讀、回覆、入群、按 Star、提交自介 PR 或在活動留言，也不催辦後續步驟。邀請記入日誌後即結束該對象的處理，不逐一重開對話查看後續通知。只有明確的客服問答需要接續；邀請送出後，AI 不再在私訊回覆，客服問題於 Discord 接續或交給負責人。

## 開始前

確認本次使用的帳號、處理範圍、負責人與拍板的人，以及可用的邀請和申請入口。先查看[邀請日誌](<../../logs/邀請日誌.md>)，避免多人同時處理同一人。只整理或試跑時，不接受陌生訊息、不發訊息或邀請。

本次完整名單、個別對話入口、授權範圍及負責人應可直接取得；現行 SOP 提供公版，邀請日誌提供已送出結果。資料足以判斷時直接執行，不把翻歷史討論或修舊工具當作前提；資料有矛盾才回查來源。

新發起招募時，先在貼文說明目的、參與方式及聯絡管道；收到留言或私訊後，依下列步驟處理。若是接手他人的招募，先了解貼文內容與先前回覆。

## SOP

1. **只看待處理對話。** 依邀請日誌略過已邀請對象，只查看尚未處理的招募留言、續串與私訊，讀取理解問題所需的完整前後文及必要圖片。已邀請對象只有明確客服問題或上次送出結果不明時才接續處理，不為一般通知、致謝或貼圖重開對話。

2. **確認有沒有處理過。** 查看[邀請日誌](<../../logs/邀請日誌.md>)，再以渠道及私人完整帳號核對實際對話與其他可存取紀錄，以及自己或其他負責人的最新回覆，合併同一人的不同來源。曾答應邀請不等於已發送；送出結果不明時，先查看實際對話，確認前不重送。

   例子：你發起招募後，同一人先留言「想加入」，又傳來私訊。另一位負責人已回覆「稍後提供加入方式」，但未確認是否已發送邀請。先把兩個來源合併，查對話與紀錄；確定沒發過，再接續邀請。

3. **必要時回答客服問題，確認加入意願。** 邀請送出前，只針對對方實際提出的客服問題依現行制度回答。沒有問題且已明確表達加入意願時，直接進入邀請步驟。只表達支持或被別人標記，不代表同意加入；先問本人。遇到尚未決定的規定，交給拍板的人確認。邀請送出後的客服問題在 Discord 接續或交給負責人，AI 不再於私訊往返。

   例子：你原先邀請一位前輩分享創業經驗，對方答應交流。這是後續訪談對象，不能把答應分享當成願意加入而發一般邀請；對方日後另行表達加入意願時，仍依相同制度處理。

4. **提供邀請與加入說明。** 本人願意參與後，再看一次最新對話，核對收件人、內容、既有邀請及有效入口，確認沒有其他人已處理。記下準備發送的動作，再提供目前社群的邀請與申請說明。同名或同頭像不能當作跨平台身分證據，須由本人確認。沒有有效入口時先保留待確認；不要自行建群、核准申請或授予權限。

   **Payload（公版訊息）**

   公版使用純文字，不含粗體星號、程式碼框或其他 Markdown 裝飾；保留步驟編號及完整連結。

   每批開始前確認正式連結及 Discord 邀請仍可開啟，並按下方分則範圍準備純文字。公版有變時重新核對分則；原文只維護在此處，不另建第二份公版。每則貼入後核對內容完整、沒有被平台截斷，再送出；如果超長，清除截斷草稿，依原段落調整分則，保留全文、順序及所有連結，不自行刪改內容。不將單次實測長度當成永久平台上限。

   依序送出各則並逐則回讀，距離上一次實際送出 Threads 訊息至少 60 秒才送下一則。全部分則均已送出且回讀後，才記為該人的邀請完成。下方「第一則／第二則」是操作標示，不複製到私訊。

5. **確認訊息已送出。** 發送後回讀，確認公版訊息已送出。結果不明時，先核對實際對話，確認前不重送。

6. **記入邀請日誌。** 確認送出後，在[邀請日誌](<../../logs/邀請日誌.md>)追加時間、暱稱、遮蔽帳號、渠道、操作者及必要備註，不記邀請內容摘要或後續處理結果。帳號先採預設遮蔽中間 5 個字元，不足 5 個則全部遮蔽，以 `*` 表示；完整帳號及證據另外私人保存。遮蔽帳號不能作為唯一去重依據，須核對渠道、私人完整帳號及實際對話。尚未確認送出的邀請不記入日誌；未完成的發送或未讀範圍另外交接給拍板的人及後續負責人。

## 中斷與交接

- 私人逐人紀錄保存準備發送、每則實際送出與回讀結果，以及完成後對應的邀請日誌。草稿不算送出；只送出部分公版不算邀請完成。
- 接續時先核對未完成動作與實際對話，只補尚未送出的部分。送出結果或最近一次發送時間不明時，先查明；確認前不重送，也不發下一則。
- 單一對象無法聯繫，且已確認沒有未決發送時，記下原因，繼續其他已授權對象。登入、驗證或頻率限制影響整個帳號時，停止受影響的發送，依注意事項處理，不把帳號問題當成單人問題略過。
- 批次完成數、剩餘名單及接續說明，從私人逐人紀錄整理，不另外維護一套完成判斷。每次交接前核對摘要與逐人紀錄；舊中斷說明保留為歷史，不能繼續當成目前指令。若紀錄矛盾，先核對既有送出依據，仍不明才依實際對話確認，不直接重送。
- 公開邀請日誌只記已確認送出的完整邀請；未完成個案保留在私人名單交接，不以待處理或失敗紀錄冒充成功。批次摘要只報完成數、剩餘範圍與必要的個案原因，不追蹤受邀者後續行動。

## 注意事項

- 同一邀請不要重複發送；送出並記錄後不主動查看或回覆後續私訊，不回覆一般致謝、貼圖或閒聊。明確客服問題依前述方式接續，避免無目的往返。本人拒絕或要求停止聯絡時，停止主動邀請。
- 每次送出 Threads 訊息後，固定等待 **60 秒**，才可送出下一則。等待期間可閱讀與記錄，不得發送訊息。遇到頻率限制、登入或驗證阻擋，停止受影響的發送，記下停止位置；恢復前先確認先前動作的結果，不連按或換帳號繞過。
- 已送出的邀請記入日誌；完整帳號、私人對話、聯絡資料與截圖證據存放在有權限的位置，不貼進公開 repo；日誌不放可還原完整帳號的連結；邀請連結也不要未經確認就公開。
