# Discord 與加入入口的改動提案

本附件保存 [dc infra Plan](plan.md) 的盤點提案。使用者已授權本輪 Discord 入口更新，執行範圍與結果見 Plan 的「本輪執行：Discord 更新」；其餘網站與管理接續項仍為候選，未因本輪授權自動發布。只修正文案與已存在設定的差異，沒有新增入會條件、工作承諾、職位或管理權。採納後文案應回到 specs 的主要維護位置，本附件保留提案身分。

## 發布前要先核對的條件

[憲政制度](<../../specs/01-制度/[機制] 憲政制度.md#申請與成員資格>)仍明列入會生效點修訂的有效採納與公布條件。這輪未核實生效證據；下方候選文字以現行入口及適用制度承接，不把公告更新當成資格規則已生效。若採用明寫「審查通過並合併」的版本，須先取得既有有效採納證據，再同步 topic、Guide、網站及審查說明；無證據就保留待處理，不請新人自行判讀制度新舊。

發布人須具所需有效職責及平台能力；[Onboard](<../../specs/02-R&R/[Role]Onboard-篩選與加入接續.md>)與[基建維護](<../../specs/02-R&R/[Role]基建-Repository維護.md>)尚有任命／生效核對，不能只因名列 assignment 或看得到編輯按鈕就當作已授權。使用者 review 本附件也不取代組織正式任命。

## onboard 釘選訊息

位置：[原釘選訊息](https://discord.com/channels/1563453138810306612/1563456791050977341/1564254596208271400)。保留原討論與回覆；更新原訊息並回讀釘選。若原訊息不可編輯，先提出替換方式，確認新釘選有效後處理舊釘選，不同時留下兩套操作說明。

本節舊候選已由使用者要求改為直接提供 Agent prompt。正式文案維護於 [Discord Setup 的 onboard 釘選文案](<../../specs/05-社群基建/[規格]Discord-社群-Setup.md#onboard-釘選文案>)，不在此重複維護全文。直接修改原訊息並回讀釘選；既有討論與連結保留。

## Topic 與 Server Guide

當期 onboard topic、Server Guide Welcome Sign、第一項任務與 announcements／mod-log topic 以 [Discord Setup](<../../specs/05-社群基建/[規格]Discord-社群-Setup.md>) 為維護來源，原候選全文不再重複維護。

保留三項 Guide 任務，逐項核對 visits 完成條件、順序與 Next；不新增問卷或 Resource Pages。welcome、rules 保留原有規範與頻道導覽，更新 canonical repo 入口。welcome 補組織建設中與 onboard Agent prompt 指引；語音提及須先核對同一 channel。

## 語音與管理接續

初次盤點時語音叫 meeting，specs 與 welcome 寫 lounge。後續已以 Copy Channel ID 核對同一頻道與原聊天，完成更名為 lounge，結果見 [Plan](plan.md#discord-實際執行結果)。初次提案要求先核對同一頻道才更名、不新建或刪除頻道；這項限制已沿用。

管理接續目前只核到 @everyone 與 owner 存取 mod-log。先依 assignment 連回有效任命、本人接受與職權，再準備最小必要權限；第二人的有效 Role 必須明列接續責任與能力。沒有這些依據，就記接續不足，不以新建 Administrator Role 或共享 owner 帳密當解法。普通加入者公開交流／本人活動權限保留。

## 網站及 repo 入口的確切改動對象

| 已發布或有效入口 | 問題 | 預定正確目的地與核對 |
|---|---|---|
| 官網自介說明 | Members/README（自介說明入口）的大小寫不符，實查找不到頁面 | 新 org 下的 members/README.md；實際點開可看到照片、Contributors 與提交步驟。 |
| 官網憲法 | constitution（舊憲法路徑）找不到頁面 | 新 org 下的 specs/01-制度/憲法.md；實際開啟十二條現行憲法。 |
| 官網申請制度 | 舊獨立申請制度檔已不存在 | 新 org 下的 specs/01-制度/[機制] 憲政制度.md 的「申請與成員資格」；不只更換 org 字串。 |
| 官網自介起草與提交 | 已發布文案／操作尚未完整反映 members；本機有未提交修正 | 核對網站既有 links、IntroBuilder、intro-template 與 YAML 修改，補本人照片及 assignment 的接續；不宣稱單一「建立自介檔案」按鈕已送齊整份申請。先沿用現有工作再補必要修改。 |
| README clone prompt／GitHub Setup／Discord Setup／相關有效 SOP | 舊 org 根 URL 可轉址，但名稱已變 | 統一 canonical URL；歷史紀錄原話不改。網站 source 的 links.ts 只是改動位置，真正完成依據是部署後 href 與使用路徑。 |
| 網站頁面與 Guide 的資格文字 | 本輪尚未核實規則切換採納時間 | 先按本附件的制度指涉版本處理；若查到有效採納，再明寫適用生效點並對齊規格。不得因修連結就回溯改判既有資格。 |

## 如何核對

由一位尚未申請的加入者從官網／Discord 任一入口開始，能認識組織、先交流、找到現行自介及分工說明，再自行決定申請；依原制度完成本人確認與正式審查。驗收範圍及目前尚未實測的項目見 [Plan 驗收](plan.md#驗收與尚未驗證處)。初次盤點沒有送出訊息、修改設定或部署網站；後續已授權的 Discord 執行結果見 Plan，網站仍不在本輪執行範圍。
