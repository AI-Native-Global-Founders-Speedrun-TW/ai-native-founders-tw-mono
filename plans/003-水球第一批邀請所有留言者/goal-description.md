### 名單欄位怎麼用

- `accounts`：以完整 Threads 帳號為 key 的去重名單；目前 335 人。
- `account`：本人帳號；去掉 @、轉小寫，保留點與底線。同名或同頭像不當同一人。
- `sources[].channel`：來源文章或私訊渠道。
- `sources[].url`：直接開啟該人的原留言、被標記位置或私訊對話。
- `sources[].summary`：已取得內容的整理，用來判斷下一個動作。
- `sources[].inspection`：已讀全文、僅列表預覽或歷史待回查；決定需要補讀哪裡。
- `sources[].kind`：本人留言、被標記者、被引用者、私訊或歷史線索。
- `invitation_status`：目前是否已確認送出，不能只憑「想加入」就改成已邀請。
- `next_step`：下一個具體動作；每人處理後更新，讓中斷後能直接接續。

由執行 agent 直接讀寫完整名單並操作瀏覽器，現行 SOP 就是 truth；LINE 流程已廢棄，不使用舊邀請 skill 或以輔助腳本相容性作為執行前提。每次發送前，直接在主表對應帳號下保存本次動作與開始時間；確認成功後保存送出時間、回讀依據及對應的公開日誌位置。這些記錄由 agent 在執行時完成，不是水球需先補好的基礎建設；不另開少數人的第二份名單。

1. 使用已登入的 Chrome「水球球特務」profile，核對 Threads 帳號為 `johnny850807`。由單一 agent 操作，不與其他 agent 同時發送。
2. 先以私人完整帳號與邀請日誌略過已確認送出並記錄者；只有送出結果不明或 SOP 允許的明確客服情況才查已邀請者。從主表選下一位：先處理明確想加入的私訊，再處理明確想加入的留言，接著處理需要確認意願的人。每處理完一人，就繼續下一位，不逐人等水球批准。
3. 直接開此人的 `sources[].url`，讀必要前後文與最新對話，核對水球或其他負責人是否已邀請。曾答應週末邀請不算已送出；同一人只邀一次。
4. 明確想參與且未邀請者，依 SOP 進入發送。只有支持、表情、被標記或詢問 YC 活動的人，先依 SOP 確認本人意願。本人拒絕或要求停止聯絡時立即停止；不要把活動名額與本組織加入混為一談。
5. 發送前先在私人主表記下本次帳號、預計動作與開始時間，核對收件人及公版全文再送出。接受陌生訊息與發送分開記錄；每次送出 Threads 訊息後固定間隔至少 60 秒，等待期間可處理閱讀與記錄。
6. 送出後回讀，確認已向正確對象送出完整公版，再依 SOP 追加邀請日誌，回寫私人主表的送出依據與日誌位置。只按過送出或輸入框清空不算成功。
7. 已確認送出並完成記錄的人結束處理，不再查看已讀、入群、自介 PR、致謝或貼圖。需要接續的明確客服問題依 SOP 在 Discord 處理或交負責人。
