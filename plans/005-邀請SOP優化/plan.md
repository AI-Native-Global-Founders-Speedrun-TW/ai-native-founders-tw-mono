## ORID：事實（Objective）

1. 五人共十則訊息全部送出、回讀並記入日誌。最短間隔約 69 秒，符合現行 SOP。這只證明送出工作完成，沒有觀察邀請轉換或閱讀體驗。
2. 首次貼入完整公版，平台顯示訊息太長，輸入被截斷。未送出即清除，後續按原段落拆成兩則。這是本次介面的實測，不宣稱所有平台或未來版本都有同一上限。
3. 水球要求去除 Markdown 裝飾後，SOP 公版已改純文字；前兩位保留已送出版本，後三位改用新版，未重送。
4. 前一版候選把分享經驗的前輩與一般加入者放在一起。水球更正：這類對象留給後續訪談。已調整，沒有向被排除的對象發一般邀請。
5. 回顧時重新核對私人資料：五人的逐人紀錄及公開日誌均完成，但批次摘要仍保留完成兩人、剩餘三人及草稿中斷敘述。這是紀錄矛盾，並非三人實際未送出。這是提案時觀察；本輪已依逐人紀錄校正摘要，保留舊值為歷史。
6. 現行 SOP 已規定意願判斷、去重、發送前核對、回讀、分則全部完成才記日誌、間隔、例外停止及不主動追蹤。優化不能把已存在的承諾再寫成另一份規則。

## ORID：反應（Reflective）

使用者已表達的判準：希望執行力更強、不要雜訊；現行 SOP 是 truth；最後一次確認後由 Agent 執行；前輩留作訪談；訊息不用 Markdown 裝飾。本輪新增要求是 problem-solution fit、don't overengineer、fit solution。

AI 的回顧：試邀請暴露的是準備內容與實際平台不合、對象目的曾被誤判，以及紀錄接續有矛盾。長文可能帶來閱讀負擔，但沒有受邀者回饋可證明；不能把 AI 的感受寫成使用者或受邀者的反應。

## 使用者目前覺得的 Problem

水球已採納下列 Problem 對應的三項局部修改，依[決策 002（採納局部優化）](decisions.md#決策-002採納局部優化)。

### 邀請對象與後續訪談對象混用

選名單時把願意分享經驗等同願意加入，可能發出不適合的邀請。一般意願判斷已在 SOP；待補的是這次實際發生的訪談例子，不需要另建人物評分。

### 公版不能直接完整傳送

公版在實際介面超長，必須當場清除並分則。現行 SOP 已允許按段落分則；待補的是執行前準備，使下一批沿用公版時不用再碰一次截斷。

### 中斷後的紀錄可能導致重送

逐人結果與批次摘要不一致，下一個 Agent 可能接錯位置。現行 SOP 已要求不明時核對對話；待補的是現況資料不應由多處各自宣告，及交接時如何以逐人結果判讀。

## ORID：解讀（Interpretive）

### 對象判斷：補一個例子就足夠

支持、加入、受訪是不同的意思。只需在現有意願判斷步驟加入「邀請分享經驗的對象留給後續訪談；不能把答應分享當作加入意願」的例子。這是聯絡目的分類，不是限制對方日後申請加入。

### 公版分則：在原處標清範圍，不維護第二份全文

保留現有公版，在其外標註本次已用過的兩則切分位置；批次準備時核對目前全文與平台可貼入內容。公版有變才重新檢查分則。標記不發給受邀者，不另做模板庫，不把實測長度寫成永久平台規定。

### 執行紀錄：先消除重複現況，不先開發系統

以逐人發送與回讀紀錄判斷完成，批次摘要由其整理。先修正已知過期摘要，把舊中斷說明標為歷史；保留實際送出版本。這不需要先做資料庫、排程器、儀表板或同步服務。只有後續反覆發現同類錯誤、人工整理成為成本，才評估小型產生摘要工具。

公開日誌與私人逐人紀錄仍各有必要：前者提供遮蔽後的完成紀錄，後者支援完整帳號去重與接續，不為減少檔案把私人資料搬到公開 repo。

### 中斷處理：區分單一對象與整個帳號

上一輪 AI 提案「結果不明可記下後繼續其他人」過於寬泛。若不明涉及上一則有沒有送出、最近一次發送時間，先查明，才能遵守間隔。登入、驗證或頻率限制影響整個帳號時，依 SOP 停止受影響的發送。只有單一對象無法聯繫且已確認沒有未決發送時，才適合記錄原因、繼續其他已授權對象。此修正已依使用者採納寫入 SOP，現行條件讀取該處。

### 縮短訊息：目前不是必要解法

把完整 Agent prompt 搬到網站、重寫結尾、簡化加入步驟，都會改變已核准文案或跨到網站。現有分則已能完整送出；沒有邀請成效證據，不把這些變動塞入本次必要範圍。保留為未採納的後續選項，不據此啟動網站修改或追蹤受邀者。

## ORID：決策（Decisional）

下列三項取捨已由水球採納，見[決策 002（採納局部優化）](decisions.md#決策-002採納局部優化)；此處保留選擇理由，不另訂操作規則。

### 已採納：在現有 SOP 做三項局部修改

- 對象判斷補上後續訪談的例子。對應「邀請對象與後續訪談對象混用」；效果是依實際聯絡目的決定下一步，不新增資格條件。
- 公版原處標示分則範圍，並補批次開始前核對。對應「公版不能直接完整傳送」；保留原文及唯一維護位置，不另外複製全文。
- 補清逐人完成紀錄與中斷接續的關係，以及單人問題和帳號問題的區別。對應「中斷後的紀錄可能導致重送」；沿用現有日誌、私人名單及停止條件。

### 已採納：修正既有私人摘要，作為一次資料修正

依五人的實際逐人紀錄校正批次完成／剩餘摘要，保留歷史原文。這不是新的 SOP 成果，也不需要重新發訊息。是否移除多餘現況欄位，先查既有讀取者；最小修正是校正內容並清楚標明歷史。

### 本次不做：縮短公版、搬 prompt 到網站、建自動化系統

現有分則已解決送出限制；未證明網站改版會改善邀請效果。先不改已核准文案，不加追蹤、不建 CRM、不修舊 LINE 工具、不增加逐人請示與評分。這些是本次 scope 取捨，不是永久禁止。
